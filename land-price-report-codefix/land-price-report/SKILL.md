# 지가동향 시황보고서 생성 스킬

## 0. 핵심 원칙 (반드시 준수)
- **숫자는 파이썬만 산출한다.** 서술에 들어가는 모든 수치는 `result.json`에 존재하는 값만 사용하고, 임의로 지어내지 않는다.
- **변동률 ≠ 실거래.** 지가변동률은 *조사 표본지에 대한 가격조사 결과*다(표준지 평가가 아님). 실거래가 희소한 권역은 상승을 단정하지 말고 "조사 표본가격·지역 여건에 반영된 것으로 분석됨"으로 제한 해석한다.
- **공표 문서**다. 과장 표현을 쓰지 않고, 개발사업은 호재로만 쓰지 말고 추진 단계·실수요 유입 여부를 함께 적는다.
- 최종 변동률 선정·공표 책임은 담당자에게 있다. 서술은 담당자의 판단을 돕는 근거 정리다.

## 1. 입력 파일 (업로드 폴더에서 자동 인식)
파일명에 아래 키워드가 포함되면 자동으로 찾는다. (정확한 파일명이 아니어도 됨)
| 용도 | 키워드 | 비고 |
|---|---|---|
| 실거래(매매) | `실거래` 또는 `매매` | 연도별 여러 개 가능 (전부 병합) |
| 지가동향 | `지가동향` | 당월 1개 |
| 인구 | `인구` | 주민등록인구 |
| 세대수 | `세대` | 주민등록세대수 |
| 네이버 매물 | `매물` | 당월·전월 2개 (월 표기로 구분) |

## 2. 실행 순서

### (1) 데이터 분석 → result.json
```bash
cd scripts
python analyze.py [기준연월] [업로드폴더] [출력경로]
# 예) python analyze.py 2026-05 /mnt/user-data/uploads /home/claude/result.json
# 기준연월 생략 시 실거래 데이터의 최신 신고월을 자동 사용
```
`result.json`에는 다음이 모두 계산되어 있다: 당월/전월/전년 거래 요약·증감, 12개월 추이, 읍면동·용도지역·이용상황 집계, 외지인 시군구/이용상황/자본성격(개인·법인·연령·목적), TOP10(전체·외지), 지가 변동률(당월·누계·용도·이용·권역), 권역별 판단근거(judge), 권역 전월대비 추세, 인구·세대, 네이버 매물·호가조정·괴리율.

### (2) 보고서 생성 → HTML
```bash
python render.py [result.json경로] [narratives.json경로(선택)] [출력폴더]
# 예) python render.py /home/claude/result.json narratives.json /mnt/user-data/outputs
```
- 제목·파일명·기준월은 result.json의 meta에서 자동 생성된다.
- **표·차트·판단근거표·인구표·TOP10·매물표는 result.json으로 100% 자동 생성**된다.
- **서술 문단**은 매달 갱신이 필요하다(아래 3·4 참고).

## 3. 매달 갱신이 필요한 서술 (가장 중요한 작업)
다음 블록은 그달 데이터·현안에 따라 달라지므로 **result.json을 읽고 새로 작성**한다. 현재 `render.py`에 들어 있는 서술은 직전 달(2026-05) 예시이므로, 새 달에는 해당 문단을 교체한다.

1. **Key Takeaways / Executive Summary** — 당월 요약(summary·증감 값 인용)
2. **6장 권역별 동향(5개 권역)** — 권역별 거래 흐름·상승/제약 요인·관찰 포인트
3. **6장 ③ 뉴스 3건** — 그달 나주 부동산·개발 관련 뉴스 (검색·사실확인 필요. 철도 신설 등 확정성 낮은 사안 제외)
4. **7장 용도지역·이용상황 변동 사유**
5. **8장 판단근거 종합 코멘트** — judge 데이터 기반
6. **9장 읍면동 상승 사유(상위 6개 권역)** — sec8 데이터 기반, 4단계 구조
7. **10장 결론·모니터링 시사점**
8. **부록2 뉴스 심층분석 3건**

작성 시 `assets/narrative_rules.md`(문체·금지어·구조 규칙)를 반드시 따른다.

### 3-1. narratives.json (단순 서술 블록 교체)
일부 단순 서술 블록은 `narratives.template.json`을 복사해 값만 채운 뒤 render.py에 전달하면 자동 교체된다(코드 수정 불필요).
- 교체 가능 키: `kt_시장국면`·`kt_수요주체`·`kt_가격흐름`(핵심요약 3), `exec_총괄`·`exec_수요`·`exec_요충지`(개요 3), `sec6_종합`(6장 종합), `sec10_결론`(결론 첫 문단).
- 마크업: `**볼드**`, `[r]상승·빨강[/r]`, `[b]하락·파랑[/b]`.
- 빈 문자열로 두면 render.py에 내장된 직전 달 서술이 유지된다.
- 실행: `python render.py result.json narratives.json /mnt/user-data/outputs`

### 3-2. 구조 블록 (render.py 직접 편집)
표·배지·제목 구조가 있는 블록(6장 권역별 동향, 6장·부록2 뉴스, 7장 변동사유, 9장 읍면동 상승사유)은 narratives.json으로 교체하기 어려우므로, result.json을 근거로 `scripts/render.py`의 해당 문단을 직접 수정한다.

## 4. 서술 작성 절차 (권장)
1. `result.json`을 연다.
2. `assets/narrative_rules.md`의 규칙(종결어미·금지어·권역 4단계·희소권역 제한해석·마무리 문장)을 적용한다.
3. `judge` 항목의 `플래그`('실거래 주도'/'조사표본 주도')에 따라 9장 마무리 문장을 결정한다:
   - 실거래 주도 → "○○ 요인이 ○○면/동 지가 상승을 견인함."
   - 조사표본 주도(거래 희소) → "○○ 입지/개발 기대가 조사 표본가격에 반영된 것으로 분석됨."
4. 뉴스 3건은 1차 소스(나주시청·전남도 보도자료, 국토부·LH 고시) 우선으로 검색·확인하고 추진 단계를 함께 적는다.
5. 작성한 서술로 `render.py`의 해당 문단을 교체하거나 `narratives.json`에 채운 뒤 render.py를 실행한다.
6. **검증**: 생성된 HTML의 서술 숫자가 result.json 값과 일치하는지 대조한다.

## 5. 권역 사전 / 설정 변경
- 권역 구분(`ZONE_DEF`)·읍면동 토큰(`ZONE_TOKENS`)·지역명(`REGION`)은 `scripts/analyze.py` 상단에서 수정한다.
- 다른 시·군으로 확장하려면 REGION과 권역 사전을 해당 지역에 맞게 교체하면 된다.

## 6. 산출물
`{지역}_토지시장동향_시황보고서_{연도}년{월}월.html` 형식으로 출력 폴더에 저장된다.
